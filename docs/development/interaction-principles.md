# 交互原则

本项目不是普通 CRUD 后台，而是 AI 小说创作工作台。任何前端交互都必须先确认信息架构，再写代码。

## 1. 两层信息架构

### 书架层

书架层只负责：

- 查看已有小说
- 快速切换小说
- 新建小说入口
- 删除/归档小说
- 进入小说工作台

书架层不出现项目内资源导航，例如：人物、世界观、伏笔、道具、章节正文。

### 工作台层

进入某部小说后，才展示项目内资源：

- 小说信息
- 大纲规划
- 章节正文
- 人物
- 世界观
- 势力
- 地点
- 道具
- 伏笔
- 时间线
- 小说记忆
- 生成任务
- 项目设置

## 2. 新建小说不是弹窗

新建小说是创作入口，不是后台表单。

必须提供两个入口：

- 手动创建：用户直接填写基础信息。
- AI 创建：用户输入故事想法，由 AI 生成小说档案。模型未接入前，只能显示“即将接入”，不能假装可用。

禁止把新建小说做成普通 Modal 表单。

## 3. 不展示未实现功能

页面上不显示未实现的操作按钮。

允许展示工作台导航骨架，但必须是结构性导航，不得让用户误以为功能已完成。

例如：

- 可以展示“AI 创建，即将接入模型”。
- 不可以展示可点击的“AI 生成”并假装成功。
- 不可以展示“查看生成记录”，除非生成记录模块已完成。

## 4. 类型和标签是有限集合

类型和标签必须来自 `Genre` 和 `Tag` 表。

禁止在 Project 上长期使用自由文本类型字段。

## 5. UI 修改前先确认

涉及以下内容时，必须先给出交互图或说明并等待确认：

- 信息架构变化
- 新页面入口
- 工作台导航变化
- 新建小说流程变化
- AI 生成流程变化
- 复杂表单/分组编辑页

## 6. 产品文案和开发文案分离

正式 UI 只出现用户可理解的产品文案。

技术栈、开发计划、TODO、接口状态等放在 README 或 docs，不放产品页面。

## 7. 工作台内模块归属

人物、世界观、势力、地点、道具、伏笔、时间线、小说记忆都必须归属于某个 Project。

这些模块不得出现在全局层级。
